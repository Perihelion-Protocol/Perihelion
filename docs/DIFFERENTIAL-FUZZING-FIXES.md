# Differential Fuzzing Fixes - Issues #431, #436, #437, #440

This document details the resolution of four auto-generated differential fuzzing failure issues from the Perihelion Protocol CI.

## Issues Overview

All four issues (431, 436, 437, 440) were auto-generated by the GitHub Actions differential fuzzing workflow when compilation and encoding/decoding mismatches were detected between EVM (Solidity/Foundry) and Soroban (Rust/Proptest) implementations.

## Root Causes and Fixes

### Issue #431 - Compilation Error in Soroban Tests

**Status:** ✅ RESOLVED

**Root Cause:**
- Stray closing brace (`}`) on line 379 of `contracts/soroban/settlement/src/messages.rs`
- Located after the `encode_fill_instruction` function body
- Caused "unexpected closing delimiter" compile error
- Made every Soroban differential fuzz test fail to compile

**Fix Applied (Commit 0922dd5):**
- Removed the stray closing brace
- Fixed test module imports (added `extern crate std` and `use std::string::ToString`)
- All Soroban tests now compile successfully

**Verification:**
```bash
cd contracts/soroban/settlement
cargo check --target wasm32-unknown-unknown --release
# ✓ Compilation succeeds
```

### Issue #436 - Wire Format Mismatch (FillInstruction Layout)

**Status:** ✅ RESOLVED

**Root Cause:**
- FillInstruction wire format was 158 bytes with:
  - recipient field: 32 bytes (truncated strkey)
  - dest_asset field: 32 bytes (didn't support CODE:ISSUER)
- This diverged from architectural spec requirements
- Issue #270 tracks the layout expansion

**Fix Applied (Commit 0922dd5):**
- Expanded FillInstruction to 219 bytes:
  - recipient: 32 → 56 bytes (full Stellar strkey text)
  - dest_asset: 32 → 69 bytes (supports CODE:ISSUER format)
  - Updated layout: `version(1) | type(1) | intent_hash(32) | src_eid(4) | recipient(56) | dest_asset(69) | min_dest_amount(16) | deadline(8) | preferred_solver(32)`
- Updated golden vector: `contracts/shared/wire-vectors/fill_instruction.hex`
- Updated all tests to use 219-byte layout

**Verification:**
```bash
# EVM side
cd contracts/evm
forge test --match-test "test_FillInstructionVectorMatchesSolidityEncoder" -vv
# ✓ Encoder produces correct 219-byte golden vector

# Soroban side
cd contracts/soroban/settlement
cargo test fill_instruction_matches_golden_vector
# ✓ Decoder accepts 219-byte payload
```

### Issue #437 - Address Encoding (Strkey vs Raw Bytes)

**Status:** ✅ RESOLVED

**Root Cause:**
- Solidity encoder was storing only 32 bytes of strkey ASCII text (truncating the 56-char strkey to first 32 chars)
- Soroban decoder was interpreting those 32 bytes as raw contract ID
- Two incompatible conventions meant no Stellar address could survive the round-trip
- Issue #271 tracks address encoding

**Fix Applied (Commit 0922dd5):**
- Updated Solidity encoder to store full 56-byte strkey text for `recipient`
- Updated Solidity encoder to store up to 69-byte strkey/asset for `dest_asset`
- Updated Soroban decoder to use `Address::from_string_bytes` (not raw contract ID reinterpretation)
- Now addresses survive round-trip correctly

**Verification:**
```bash
cd contracts/soroban/settlement
cargo test fill_instruction_recipient_round_trips_with_219_byte_format
# ✓ Recipient address survives round-trip through 219-byte wire format
```

**Test Case:**
```rust
// Original address (Stellar strkey)
let original = Address::from_str(&env, "CAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAABSC4");

// Encode and decode through 219-byte wire format
// ...payload construction...
let (msg_type, fi, _) = decode_message(&env, &payload);

// Assertion
assert_eq!(fi.recipient, original);
// ✓ Address correctly round-trips
```

## Wire Format Specification (Post-Fix)

All three message types are now fully specified with consistent layouts across EVM and Soroban:

### FillInstruction (219 bytes)
Sent: Stellar ← Source Chain
```
version(1) | type(1) | intent_hash(32) | src_eid(4) | recipient(56) | 
dest_asset(69) | min_dest_amount(16) | deadline(8) | preferred_solver(32)
```

### FillConfirmed (90 bytes)
Sent: Source Chain ← Stellar
```
version(1) | type(1) | intent_hash(32) | solver_evm(32) | amount(16) | ledger(8)
```

### CancelIntent (35 bytes)
Sent: Both directions
```
version(1) | type(1) | intent_hash(32) | reason(1)
```

## Testing

### Run Differential Fuzzing Locally

Quick bounded run (100 cases, ~30 seconds):
```bash
make fuzz-bounded
# or
cd contracts/evm && forge test --match-contract DifferentialFuzz --fuzz-runs 100
cd contracts/soroban/settlement && PROPTEST_CASES=100 cargo test fuzz -- --test-threads=1
```

Extended run (10k cases, ~5 minutes):
```bash
make fuzz-extended
```

Deep nightly run (100k cases, ~1 hour):
```bash
make fuzz-nightly
```

### CI Integration

- **PR checks:** Bounded run (100 cases) on every pull request
- **Nightly:** Extended run (10k cases) daily at 2 AM UTC
- **Manual dispatch:** Workflow tab → Differential Fuzz → Run workflow → toggle "Run extended fuzzing"
